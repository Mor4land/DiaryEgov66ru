# Product

## Platform

web

## Users

**Ученики 5–11 классов Свердловской области** (основная аудитория) — открывают Telegram или MAX, чтобы узнать домашнее задание и расписание, не заходя в региональный дневник через Госуслуги. Пользуются с телефона, в основном вечером и утром перед школой.

**Родители** — привязывают ребёнка (роль `Parent`, поле `SelectedStudentId`) и смотрят те же данные.

**Завучи** (роль `HeadTeacher`) — загружают расписание для своей школы; роль выдаётся вручную администратором по запросу на электронную почту.

**Администратор сервиса** (один человек, владелец проекта) — пользователь админ-консоли `/admin.html`. Заходит с ноутбука, обычно днём. Четыре задачи, все регулярные: проверить, живы ли боты и сервер; посмотреть пользователей и выдать роль; разослать сообщение; управлять снимками БД, техработами и кэшем.

## Product Purpose

Дать школьнику домашнее задание и расписание за одно сообщение боту вместо цепочки «Госуслуги → ЕСИА → региональный дневник». Сервис держит авторизацию за пользователя (шифрованные токены, фоновый рефреш) и кэширует данные класса, чтобы не долбить API дневника одинаковыми запросами от учеников одного класса.

Успех: ученик получает ДЗ, ни разу не открыв дневник; сервис при этом создаёт минимум обращений к API школьного портала.

## Positioning

Прямая работа с мобильным протоколом ЕСИА (`MobileEsiaClient`, PKCE S256 OAuth2) без запуска браузера, со строгой проверкой цепочки доверия сертификатов Минцифры (`RussianTrustedCertificateValidator` сверяет отпечатки SHA-256/SHA-1, без «слепых» `return true`). Playwright поднимается только как запасной путь для капчи и SSO, под семафором.

Второй механизм — агрегирующий кэш класса: один запрос к API дневника обслуживает всех учеников одного класса за один день (`SharedClassroomCacheService`, ключ `Школа_Класс_Дата`, TTL 30 минут).

## Operating Context

- Два транспорта: Telegram (`Telegram.Bot`, long polling) и MAX (`SaaSoft.MAX.Bot`, long polling). MAX регистрируется только если задан токен.
- Telegram MiniApp (React) для входа через Госуслуги и сохранения токена.
- Часовой пояс аудитории — Екатеринбург, UTC+5; в коде зашит `AddHours(5)`.
- Развёртывание: linux-x64 за Nginx, SQLite на диске, автоматические снимки БД.
- Админ-консоль — один статический файл `wwwroot/admin.html`, доступ по общему ключу в заголовке `X-Admin-Key`.
- Домен: `miragediary.space`. Источник данных: ФГИС «Моя Школа» (Госуслуги).

## Capabilities and Constraints

**Есть:** команды `/menu`, `/homework`, `/schedule`, `/alarm` (напоминание взять циркуль, линейку и прочее по тексту ДЗ); настраиваемое время трёх напоминаний на пользователя; роли Student / Parent / HeadTeacher / Admin; режим техработ с отдачей данных из кэша; шифрование токенов AES-256-GCM; автоснимки SQLite через `VACUUM INTO`; авто-детект техработ дневника (`DiaryMaintenanceException` включает резервный режим на 15 минут).

**Ограничения:**
- Метрики трафика живут в памяти процесса и обнуляются при рестарте — историю за пределами текущего запуска сервис не хранит.
- Режим техработ тоже в памяти (`MaintenanceModeService`), рестарт его снимает.
- Broadcast идёт синхронно внутри HTTP-запроса, без throttling под лимит Telegram и без ретраев.
- `ScheduleEntity` имеет ключом `OrgName` — одна школа хранит одно расписание.
- Тестов нет; CI нет; миграции EF Core не используются, схема патчится вручную в `DatabaseInitializer`.

**Терминология.** «Кэш класса» — правильное название локального агрегирующего кэша в SQLite. Прежнее название «P2P-кэш» ошибочно (см. комментарий в `Services/P2PCacheService.cs`) и не должно попадать в интерфейс.

## Brand Commitments

Название сервиса — **Mirage Diary**, админ-консоли — **Mirage Console**. Интерфейсы русскоязычные.

Пользователь закрепил визуальный мир админ-консоли: **Google Material Design 3**, светлая тема по умолчанию с переключателем на тёмную.

## Evidence on Hand

Реальные источники, которые консоль может показывать: счётчики `ServerMetricsService` (попадания в кэш класса, прямые вызовы API дневника — растут только от живого трафика), процессные метрики .NET (`WorkingSet`, GC, потоки, uptime), размер файла SQLite, список файлов снимков в `backups/`, таблица `Users` и её роли, состояние режима техработ.

**Чего нет и что нельзя выдумывать:** исторического трафика до старта процесса; hit rate, пока не было запросов; аптайма и статуса ботов, если компонент ещё ни разу не отчитался; числа получателей рассылки до её отправки.

Ранее в консоли эти пробелы были закрыты синтетикой: `ServerMetricsService` засеивал 12 часов придуманного трафика, а список событий был захардкожен в `AdminController` — и то и другое подписано в интерфейсе как «Реальные данные». Пользователь принял решение убрать синтетику и показывать честные пустые состояния.

## Product Principles

1. **Консоль не врёт.** Если данных нет — так и написано, с указанием, когда они появятся. Синтетика, заглушки и захардкоженные проценты в интерфейс не попадают.
2. **Меньше обращений к школьному API.** Кэш класса и single-flight дедупликация важнее свежести на минуту.
3. **Ученик не должен видеть Госуслуги.** Вся авторизация — забота сервиса.
4. **Ошибка входа не должна стоить аккаунта.** При сбоях портала сервис уходит в резервный режим и отдаёт кэш, а не повторяет попытки входа.
5. **Название описывает то, что есть.** Если код признал название неверным, интерфейс исправляется вслед за кодом.

## Accessibility & Inclusion

Аудитория ботов — школьники на телефонах; консоль — один администратор на ноутбуке. Требований сверх WCAG 2.1 AA пользователь не заявлял: контраст текста от 4.5:1, работа с клавиатуры, поддержка `prefers-reduced-motion`, светлая и тёмная темы.
